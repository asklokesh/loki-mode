## The 10x rule (honest interpretation)

"10x improvement" per iteration is the TARGET and framing, measured against a real
baseline, in ONE of these dimensions (pick the highest-leverage per iteration):
- **Correctness/trust**: close a fail-open/fake-green hole (each is ~infinite-x on the
  affected path -- a build that could ship broken now cannot). Loki's moat.
- **Coverage**: N-x more of a critical surface tested (e.g. 0 tests -> full coverage on
  a trust path = the risk goes from unbounded to bounded).
- **Efficiency**: measured token/iteration/wall-clock reduction on a benchmark.
- **Capability**: a new surface that unlocks a class of work not previously possible.
- **Scale/robustness**: remove a ceiling (single-lock -> concurrent, O(n^2) -> O(n)).

If an iteration yields less than 10x, I REPORT THE TRUE NUMBER and say why, then
strategize a higher-leverage next iteration. Never dress up a small delta as 10x.
