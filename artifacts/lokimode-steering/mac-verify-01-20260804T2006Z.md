## The defect

`loki verify --help` on stock macOS:

```
exit=2  stdout=0 bytes  stderr=148 bytes
autonomy/verify.sh: line 2793: syntax error near unexpected token `('
```

Under Homebrew bash 5 the identical command exits 0 with 4919 bytes. **Every
Mac user without a non-stock bash could not run `loki verify` at all.**

### Cause

One apostrophe, in a COMMENT, at `autonomy/verify.sh:2525`:

```sh
VERIFY_HOSTED_SUMMARY="$(... python3 - <<'PYEOF' ...
# ... reports the engine's partial finding ...
PYEOF
)"
```

The heredoc is quoted, so its body should be inert. But it sits inside
`"$( ... )"`, and bash 3.2 tracks quoting THROUGH the command substitution: the
apostrophe opens a quote that never closes, and the parser swallows the next
~270 lines. macOS ships 3.2.57 as `/bin/bash` permanently (Apple froze it at
the last GPLv2 release).

### Two things that made this hard, both worth recording

**The reported line is not the defect line.** bash 3.2 blamed 2793 --
`_verify_log "loki verify (deterministic-only MVP) starting; ..."` -- which is
perfectly valid. It is simply the first line after the swallowed region, and
the `(` there is the first token that cannot start a command.

**Truncation bisection cannot find it.** Every prefix of the file fails with a
bare "unexpected end of file", so prefix-cutting yields alternating
parse/error results that localize nothing. Function-boundary cuts were no
better. What worked: delete each heredoc BODY in turn and re-parse the whole
file. Exactly one removal made bash 3.2 accept it.

Confirmed with a 6-line minimal reproduction that fails on 3.2 and passes on 5.

## The guard that should have caught it

`tests/test-bash32-parse.sh` already existed, and already documented this exact
apostrophe-in-heredoc failure from 2026-07-28. It still missed this one,
because its list covered **9 test scripts and zero shipped entry points**.

A guard that checks the tests but not the product is checking the wrong
artifact -- the same lesson CLAUDE.md records about the packaged tarball.

Extended to check `autonomy/{loki,verify.sh,run.sh,completion-council.sh}`
first, never eligible for KNOWN_BROKEN, plus the end-to-end symptom: help must
exit 0 AND print >200 bytes, since exit-2-with-zero-output was the original
shape and a bare exit check would miss a silent variant.


So the tarball check discriminates rather than passing for free.

`npm pack --dry-run` confirms both entry points ship:
`autonomy/loki` (1.4MB), `autonomy/verify.sh` (135.9kB).

**Deliberately NOT added to the guard**: a full `npm pack` costs ~40s per run,
and `autonomy/` ships wholesale and unmodified, so the source-tree parse check
already covers the same bytes. The tarball run is recorded here as one-time
evidence instead of a per-run cost. If `files[]` ever stops shipping
`autonomy/` wholesale, that reasoning expires.
