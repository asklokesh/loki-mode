## The defect

`tests/test-model-override.sh:827` asserts three legs; two were already correct.

| Leg | Expected | Before |
|---|---|---|
| runner dispatch | `opus` | `opus` -- correct |
| runner tier (pre-collapse) | `fable` | `fable` -- correct |
| estimator quote | `Opus,Sonnet` | `Opus` -- **mismatch** |

`autonomy/loki:18342` prices iteration 0 as Opus (the fable architect pass
collapsing to opus) and every LATER iteration via `_priced_model_for`, which
defaults to Sonnet since v7.104.0. `Opus,Sonnet` therefore requires
**iterations >= 2**, and the fixture no longer produced one.

Measured on the fixture, byte-identical to v7.104.0 where this passed 66/0:

| Binary | tier | iterations | nonzero models | assertion |
|---|---|---|---|---|
| `766219ac` (v7.104.0) | simple | **4** | `Opus,Sonnet` | passes |
| `6dff2626` (HEAD before) | simple | **1** | `Opus` | **fails** |

The complexity TIER never changed. Only the iteration count for a simple PRD
fell, and with one iteration the loop never reaches the Sonnet branch.

**The estimator is correct.** The assertion encoded "a simple PRD takes several
iterations", which stopped being true.

## Why enlarge and not relax

Weakening the assertion to accept `Opus` would delete the later-iteration
Sonnet attribution coverage -- removing the test's purpose to make it green.
Enlarging restores the original intent. **Non-weakening by construction: no
expected value was changed, only the input.**

`tests/test-help-no-recursion.sh` runs each probe inside
`( ulimit -u 400 ; timeout 20 ... )`. **This machine idles at ~440 user
processes**, above that cap, so the subprocess cannot fork at all and the probe
records exit 254 with zero output -- which the test reports as "the fix broke
real delegation".

Isolated, on the identical command:

| process cap | result |
|---|---|
| `ulimit -u 400` (the test's) | `fork failed: resource temporarily unavailable` |
| `ulimit -u 800` | **exit 0, 8578 bytes, 178 lines of help** |

The delegation works. Confirmed NOT caused by the held `autonomy/loki` change:
the **baseline `dda8beec` binary fails identically** under the same cap.

A first run also showed genuine fork exhaustion from my own overlapping
background jobs; that was cleared (0 leftover test processes, 441/4000 procs)
and the failure still reproduced, which is what ruled contention out and the
fixed cap in.

Worth noting the test's own header argues the ulimit "is not optional" because
an uncapped regression would take down the machine. That reasoning is sound.
The cap being a fixed 400 rather than relative to ambient load is what makes it
environment-dependent -- it fails closed on a busy machine regardless of the
code. Not fixed here: outside this task's scope.
