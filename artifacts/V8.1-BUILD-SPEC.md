# v8.1 SDK Unification - BUILD SPEC (executable, one story per commit)

## Spine + grafts (decision, source-grounded)

**Spine = Approach 1** (write-once `+set` resolver, zero call-site edits). Verified why it wins for execution: all 8 bash sites read `[ "${LOKI_SDK_X:-0}" = "1" ]` **at call-time inside functions**; all TS sites read `=== "1"` or `truthy()`, both of which accept the literal `"1"`. So a resolver that writes only `0`/`1` into the env before the loop is honored by every existing read with **no accessor migration** - avoiding Approach 2/3's all-sites migration hazard (Judge B risk #2: a lingering `:-0` silently overriding the global).

**Grafted in:**
- Approach 2's **packed-tarball-with-no-`claude`-binary CI** gate (strongest artifact proof).
- Approach 2/3's **sandbox split** (container isolates untrusted *code exec*, not the model call; the `docker sandbox create ... claude` binary-hosting is what dies).
- **Dropped** Approach 3's "de-dup two `@anthropic-ai/sdk` pins" - verified false: `@anthropic-ai/sdk` is single-pinned (`loki-ts/package.json:25`); the dual-pinned `@anthropic-ai/claude-agent-sdk` already has the version-match assert (`local-ci.sh:903`). Nothing to de-dup.

**What does NOT flip default in v8.1:** the RARV loop (`LOKI_SDK_LOOP` stays default-off), the sandbox default path, and batch (`LOKI_SDK_BATCH` default-off). v8.1 ships T1 fully, T2 opt-in, T4 as deprecation-annotation + CI, and *stages* T3 behind the strongest gate - the flip itself is a later release.

**Global safety invariants** (every story must preserve all four):
- **INV-OFF**: nothing set → byte-identical to v8 (resolver writes nothing when mode unset).
- **INV-CLOSED**: any SDK miss (no key, error, timeout, refusal, partial) → fall through to the existing sync/deterministic path; never a fake PASS.
- **INV-PARITY**: bash and TS resolve the same mode→site table identically.
- **INV-OVERRIDE**: an explicit per-site flag (even `=0`) always wins over the mode.

## STORY 1 - One-switch resolver (bash)

- **T-item:** T1
- **Files:** new `autonomy/lib/sdk-mode.sh` (~30 lines); source it once in `autonomy/run.sh` next to the config-map source (`run.sh:257`) and in `autonomy/loki` at entry (before dispatch, near `loki:16375`).
- **What changes:** Add `loki_sdk_resolve_mode()`. Reads `LOKI_SDK_MODE` (`off|judges|full`; default `off`) and alias `LOKI_SDK` (`1`→`judges`, `full`→`full`). For each of the 8 vars, write the mode-default **only if unset**: `[ -z "${LOKI_SDK_DONE_RECOG+set}" ] && export LOKI_SDK_DONE_RECOG=<default>`. Mode→defaults table (the ONLY new policy):
 - `off` → writes nothing (all resolve to their existing `:-0`).
 - `judges` → 7 judge flags=`1`, `LOKI_SDK_LOOP`=`0` (explicitly written so it can't be flipped by a stray global).
 - `full` → all 8 =`1`.
 Call `loki_sdk_resolve_mode` once, immediately after sourcing, before any judge lib runs.
- **Test:** `tests/test-sdk-mode.sh` (assert-based, no framework): `off`→all vars unset; `judges`→7=1 & LOOP=0; `full`→all=1; `LOKI_SDK_MODE=full LOKI_SDK_LOOP=0`→LOOP stays 0 (INV-OVERRIDE); `LOKI_SDK=1`→resolves judges. Plus a **source-time-read guard**: `grep -nE '^\s*(if|\[).*LOKI_SDK_' autonomy/*.sh autonomy/lib/*.sh | grep -v ':-0}' ` must return zero top-level (non-function) reads - proves the write-once ordering is safe (Approach 1 risk #1, promoted to a blocking check).
- **Acceptance:** `bash tests/test-sdk-mode.sh` green; `bash scripts/local-ci.sh` green; with everything unset, `run.sh` argv is byte-identical to pre-story (diff a dry-run env dump).
- **Rollback:** revert the one `source` line; resolver becomes dead code. Per-site flags still work standalone.
- **Invariant:** INV-OFF (write-nothing on unset), INV-OVERRIDE (`+set` guard), INV-PARITY (table must match Story 2).

## STORIES 3 + 4 - Batch API - DROPPED (empirical: no batch-appropriate site exists)

**DECISION (2026-07-14, during execution): do NOT build Stories 3 and 4.** A
codebase-wide fan-out audit (both bash and TS) found NO site that is both a
multi-call fan-out AND latency-tolerant, which is the necessary precondition for
the Message Batches API (async submit -> poll minutes-to-hours -> retrieve, 50%
cost). The two sites the spec named:
- `loki-ts/src/council/voter_agents.ts:336` is a SINGLE inlined `judgeJson` call
  (the whole council is one prompt returning `{findings:[...]}`), not an N-call
  fan-out. Nothing to batch.
- `loki-ts/src/runner/quality_gates.ts:1653` (`runCodeReview`, the real 4-reviewer
  `Promise.all` fan-out) is ON the RARV iteration critical path - it gates whether
  the loop advances. Batch's minutes-of-polling would make every code_review cycle
  block for minutes: a severe latency regression for a 50% cost cut on a
  once-per-iteration call. Wrong trade.

Every other fan-out (magic-debate Gate 12, override council, wiki regen) is
likewise in the per-iteration blocking sequence; the only bulk/offline harness
(`swebench-pro-pilot/run_batch.py`) runs N full agentic builds, not single
completions, so Batch API cannot serve it either. Building `judgeBatch` now would
be speculative machinery for a use case that does not exist (ponytail rung 1:
does this need to exist? no). If a genuinely latency-tolerant judge fan-out is
introduced later (e.g. an offline bulk-spec-enrichment or nightly re-grade batch),
revisit then with a concrete caller. `messages.batches.{create,retrieve,results}`
is confirmed present in the pinned SDK, so the door is open; we just have no
customer for it today. Task #22 closed as "won't do (no fit)", not deferred.

### STORY 3 - Batch judge helper (`judgeBatch`), fail-closed to sync

- **T-item:** T2
- **Files:** `loki-ts/src/runner/sdk_invoker.ts` (add `judgeBatch()` beside `judgeJson`); new subcommand `internal sdk-judge-batch` in `loki-ts/src/commands/` wired in `cli.ts` (beside `sdk-judge` at `cli.ts:267`).
- **What changes:** `judgeBatch(params: JudgeParams[]): Promise<(Record<string,unknown>|null)[]>`. Builds one `messages.batches.create` with `custom_id = idx`, polls `retrieve()` until `processing_status === "ended"` (interval ~10s), decodes `results()` JSONL by `custom_id`. **Bounded:** `LOKI_SDK_BATCH_MAX_WAIT` (default 600s) **derived from - and strictly less than - the loop iteration timeout** (Approach 1 risk #4). On ANY miss (create error, timeout→`cancel()`, per-item error/refusal, unmatched `custom_id`, malformed JSONL) return `null` **for that item** - caller re-runs only the nulls via existing `judgeJson`. Assert **per-item** fail-closed (not all-or-nothing) - Approach 1 risk #5.
- **Acceptance:** `bun test` green; helper never throws; degrade emits a `batch_degrade_to_sync` telemetry line so the 50% saving is observable (Approach 3 risk).

## Deferred to later, separately-gated releases (NOT v8.1)

- **T3 flip (v8.x):** flip `LOKI_SDK_LOOP` default-on for new installs; `LOKI_LEGACY_BASH=1` restores the bash spawn. **Hard pre-flip gate (all green):** (a) `sdk_stream_parser.ts` covers every event the ~350-line embedded-python parser handles (fixture replay); (b) the 3 Bun-only flags at `run.sh:17487-17493` (`--exclude-dynamic-system-prompt-sections`, `--mcp-config`, `--include-hook-events`) reconciled to one canonical set - this is the note the source itself names as the precondition; (c) `start.ts:83` unsupported-flag guard returns zero un-ported flags; (d) Story-6 tarball E2E extended to drive the **loop** end-to-end.
- **T4 forward (after T3 flip):** build the lightweight `bun + SDK` sandbox image as the default agent runtime; retire the `docker sandbox ... claude` path. Until the agent is default-SDK, a default-SDK sandbox has nothing to wrap.

## Release-ergonomics outcome (cross-cutting)

- **One knob:** operators learn `LOKI_SDK_MODE=off|judges|full`; the 8 per-site flags become a documented "advanced rollback" appendix. Future SDK sites just join the mode table - no new top-level flag per feature.
- **One SDK version to bump:** `@anthropic-ai/sdk` lives only in `loki-ts/package.json:25` (verified single-pin); the agent-SDK dual-pin is already asserted at `local-ci.sh:903`. No new de-dup work.
- **Each later legacy removal is a one-line default change** with a pre-tested escape hatch already shipped (`LOKI_LEGACY_BASH`, the sandbox deprecation) and telemetry showing when usage hits zero.

## Dependency/risk order

1→2 (parity fixture links them) → 3→4 (batch helper before wiring) → 5 (independent, low-risk) → 6 (prep + CI, gates the future flip). Stories 1,2,5,6 are default-off/no-behavior-change; 3,4 are opt-in default-off. No story flips a default.

**Skipped (YAGNI, ponytail):** mode config-file/JSON schema (3 string values don't need one); cross-iteration batch accumulation/queue (one batch per fan-out per iteration is the win); the `sdk_site_on()` accessor migration (write-once resolver makes it unnecessary - the whole reason the spine is Approach 1, not 2/3).
