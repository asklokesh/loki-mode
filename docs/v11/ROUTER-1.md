Status: plan (Architect, 2026-10-07; default-on adjustment from steering the same day). ## 1. Goal
After the R1-19 flip, every engine10 session runs on Claude Sonnet 5.5 as the default executor with Opus 5.5 attached through the native Claude Code advisor tool, so the model itself decides when it needs stronger judgment. Opus picks the executor at plan time with a recorded reason. Opus may route a task to Haiku 5.5 only when the R1-16 history and a B9 row show Haiku at outcome parity on that repo shape; a shape with no evidence stays on Sonnet. Escalation stays evidence-gated (haiku -> sonnet -> opus, and sonnet -> opus). The outcome (solve rate, time, cost) is never below raw `claude -p`, proven on the B9 scoreboard.

## 3. Engine Laws touched
- L0 (model decides, harness proves): the executor choice is made by Opus (advisor in the plan session, or the plan session itself on Opus when no advisor), returned as schema-checked JSON. The harness adds no regex or `if` about repo shape, language or task wording. Harness-owned logic is limited to mechanism: provider capability detection (env and version), execution-evidence triggers, and recording. `tests/engine10/l0_guard.test.ts` must stay green. The shape key (section 4.6) is a lookup into executed outcome evidence and may only move the executor up (ENGINE-LAWS H4); this is the documented exception to the L0 review rule.
- L1 amendment (R1-04, founder decision D89): "never below raw" means OUTCOME parity (solve rate, time, cost on the B9 corpus and the Parity Gate), not model identity. A Haiku executor runs only in a configuration with Parity Gate evidence: with the Opus advisor attached, or without it only if arm 4 (section 7) meets the Parity Gate; otherwise the executor is Sonnet 5.5. The executor, advisor state and any fallback reason are printed on the start line and in the receipt (no silent reduction). Escalation still goes UP: Haiku -> Sonnet 5.5 (rest of run) -> Opus for a repeated failure on Sonnet (the existing L1 path, `model_rank.ts:8`), always before STALLED. Non-Claude providers and `LOKI_ROUTER=0` keep the provider's best default and escalate to the strongest model the provider offers.
- L3 (evidence outranks heuristics): escalation fires only on rung 1/2 evidence (a code-owned FAIL repeating after a fix round, a SPEC_CONFLICT exit, a stall or limit kill) or rung 3 model judgment (the advisor's explicit recommendation). Per-shape history (H4) is executed outcome data, not a heuristic.
- L5 (every failure has an owner): only `owner` code FAIL (verify.ts) drives escalation. Harness, env and provider ERRORs never escalate and never count; an advisor that is unavailable is NOT PROVEN with owner provider, never a run failure.
- H4 (self-improving): per-repo, per-shape outcome history (executor, verdict, escalated, usd, wall time) is written at seal and fed to the Opus routing prompt and, as an evidence floor, makes Sonnet the default on a shape where Haiku lost 2 of the last 3 runs (code-owned FAIL or escalation; harness, env and provider ERRORs and NOT PROVEN outcomes do not count, L5). The floor is cleared only by a B9 row showing Haiku at parity on that shape, since Haiku never runs there again while the floor holds. NOTE: "H4" is not defined anywhere in docs/ today; R1-04 defines it in ENGINE-LAWS.md.
- L7 (outputs are contracts): the route block in the receipt, the start line and the PR line get golden tests (R1-15).

## 4. Architecture
### 4.1 Routing decision schema (written into plan-scope.json by the plan session; parsed by `runner/router/decision.ts`)
```
route: { default: "sonnet",
         units: [ { id: string, kind: string, executor: "haiku" | "sonnet", reason: string (<= 200 chars) } ],
         source: "opus-plan" | "advisor" | "default" }
```
Per-unit schema (founder refinement 2026-10-07 21:45Z; lands in 11.2.0 or 11.2.1 depending on what is merged). Opus writes the units into plan-scope.json at plan time, with a run default of sonnet. The harness never routes by task type or path regex (L0): it only executes, verifies and escalates. R1-16 history is an input to the Opus planning prompt, not a harness rule. The receipt lists the executor, the assigner and the reason per unit.
A missing or invalid unit route goes to sonnet (`{executor: "sonnet", source: "default", reason: "no route returned"}`; the superseded plan returned haiku here) plus a NOT PROVEN line (L2: fail open on work). Aliases resolve through `providers/model_catalog.json` (haiku -> claude-haiku-5-5, sonnet -> claude-sonnet-5-5, opus -> claude-opus-5-5).

### 4.2 Where the decision is made
1. Run start: advisor availability is probed (R1-06). Start line: `executor sonnet-5.5, advisor opus` (or `executor haiku-5.5, advisor opus` for a shape with earned Haiku evidence; or `executor sonnet-5.5, advisor unavailable: <reason>`).
2. Plan stage runs (normal tasks): the plan session runs on the executor with the Opus advisor attached; its brief asks it to consult the advisor and write `route` into plan-scope.json. With no advisor, the plan session itself is pinned to Opus (the single cheap Opus call) and writes the same field; a `haiku` route is then raised to Sonnet (section 4.4).
3. Plan skipped (small task, `plan.ts:55`): no extra call. Executor = history floor or shape default if one applies, else Sonnet with the advisor (post-flip default; Haiku only for a shape listed `haiku` in section 4.6), `source: default`.
4. Recorded: a `route` event (implement), run.started `route_initial`, receipt `route` block (initial decision, every escalation with trigger and evidence pointer, advisor availability, share of requests above 100K).

### 4.3 Escalation state machine (pure function in `runner/router/decision.ts`)
```
EXEC(haiku) --a: code-owned FAIL repeats after a fix round------------> EXEC(sonnet, rest of run)
EXEC(haiku) --b: LOKI_ESCALATE: <reason> marker (advisor recommended)--> EXEC(sonnet, rest of run)
EXEC(haiku) --c: SPEC_CONFLICT exit | stall | implement limit kill------> EXEC(sonnet) + one retry of that stage
EXEC(sonnet) --a or stall------------------------------------------------> fix round on opus (existing L1 path) -> STALLED
any state --harness/env/provider-owned ERROR-----------------------------> no transition (NOT PROVEN path)
```
Per-unit rule (founder refinement 2026-10-07 21:45Z): a haiku unit that fails a code-owned check is redone on sonnet, then escalates to opus; a Wall assigned to haiku gets an Opus review before implement. The state machine above is the whole-run form and is read per unit. At most one Haiku -> Sonnet transition per run (whole-run form). A SPEC_CONFLICT confirmed by Sonnet stays BLOCKED. Resume across the swap: the fix session resumes the prior session id with the new model when the SDK honors `model` on `resume` (verified in R1-12); otherwise it starts fresh with the full brief plus the prior diagnosis and records `fix_resume_why`.

### 4.4 Advisor wiring and fallback detection
- Wiring: SDK route passes `settings: { advisorModel }` (in SDK 0.3.288 `advisorModel` is a field of `interface Settings`, `sdk.d.ts:6674,8987`, not a top-level Option; R1-07 confirms the 0.3.293 shape). CLI route merges `advisorModel` into the existing `--settings` JSON or uses `--advisor` when `claudeFlagSupported` says so.
- Unavailable when any of: provider is not claude; `CLAUDE_CODE_USE_BEDROCK`, `CLAUDE_CODE_USE_VERTEX` or `CLAUDE_CODE_USE_FOUNDRY` is set; `ANTHROPIC_BASE_URL` points at a non-Anthropic host; the bundled or installed Claude Code is below 2.1.293; `LOKI_ROUTER_ADVISOR=off`; or a session reports an advisor tool error (sticky for the rest of the run, cached in runDir). Unavailable never fails a run: plan runs on Opus, the cascade still works, the receipt says `advisor: NOT PROVEN (owner provider): <reason>`. With the advisor unavailable, the executor is Sonnet 5.5 unless arm 4 of the B9 parity run shows Haiku without the advisor at parity; 11.1.0 ships Sonnet here (resolved in `decision.ts`, applied by R1-07 and R1-09), and only a later slice citing arm 4 METRICS.md rows may lower it to Haiku.
- Unknown to verify in R1-07: whether the engine10 `tools` whitelist (`providers.ts:512`, 6 tools) hides the server-side advisor tool.

### 4.5 Context cost guard (keep requests under 100K, where the Haiku price is 5x lower)
Lean briefs and the cache-stable prefix already exist (`LOKI_E10_PREFIX=lean`, `providers.ts:524`). R1-07 adds `autoCompactWindow: 100000` (the SDK minimum, `sdk.d.ts` Settings) for routed sessions. R1-08 records per request `input+cache_read+cache_creation` and writes `requests_total`, `requests_over_100k` and advisor tokens into each cost event; the receipt shows the share.

### 4.6 Per-shape defaults (a shape that fails parity routes to Sonnet instead of holding the release)
- Where it lives: `loki-ts/data/router-shape-defaults.json`, shipped in the package next to model-pricing.json. Schema `{"$schema_version":1, "_source":"<B9 run ids + RC version + date>", "shapes":{"<shape_key>":{"executor":"haiku"|"prior-default","evidence":"<METRICS.md row ref>"}}}`. Semantics inverted by the 2026-10-07 21:40Z CTO decision and refined by the founder at 21:45Z (D89 amendment): the default executor is Sonnet 5.5 and Haiku 5.5 is used per work unit when Opus assigns it. A shape is listed as `haiku` once it has earned it with a B9 row showing Haiku at outcome parity on that shape, and an absent listing means Sonnet 5.5. The shipped file and the R1-16 history are inputs to the Opus planning prompt, not harness routing rules; the harness never routes by task type or path regex (L0). `prior-default` (the `LOKI_ROUTER=0` model for that stage) stays legal for a shape where Sonnet also loses. The shipped file is empty (R1-16), so every shape starts on Sonnet.
- Shape key: Project Model `workspaceKind` plus the sorted, lowercased, de-duplicated package `runner` labels from `.loki/project.json` (both model-derived, L4; the schema has no language field, `project_model/schema.ts:20-30`, decided 2026-10-07 by the CoS after R1-16 found the gap), for example `multi-root:pytest+vitest`. A package with no runner contributes `none`. The same function (`shapeKey()` in history.ts) computes it at runtime and in the receipt (R1-15 writes `route.shape_key`), so B9 rows and runtime agree by construction. No file-pattern regex (L0).
- Seeding: `scripts/b9-scoreboard.sh --emit-shape-defaults <out.json>` (R1-17) reads each run's receipt `route.shape_key`, compares arm 2 (router) with arm 1 (raw) per shape on correctness, and lists every shape where router solve count < raw. A shape where Sonnet also loses on the confirming rerun is emitted as `prior-default`. R1-19 commits that output as the shipped file, citing the METRICS.md rows. Later B9 runs reseed it in a normal slice; removing a shape, or lowering it from `prior-default` to `sonnet`, needs a B9 row showing the lower executor at parity on it.
- Read path: `decision.ts` resolves the executor as the strongest of: Opus route, shipped shape default, per-repo history floor (R1-16, local runs; under the inverted semantics Haiku is reachable only when the shape is listed `haiku` and the history does not show Haiku losing 2 of the last 3 by code-owned FAIL or escalation -> Sonnet, cleared only by a B9 row showing Haiku at parity on that shape), the no-advisor floor (section 4.4), then Sonnet unless the shape is listed `haiku`. `prior-default` resolves to the exact `LOKI_ROUTER=0` model for that stage (R1-21 fixture semantics). Explicit `LOKI_MODEL_OVERRIDE`, `LOKI_CLAUDE_MODEL_DEVELOPMENT` or `LOKI_ROUTER_EXECUTOR` still win. Evidence rungs never lower a model: a shape default can only move the executor up. The shape key is a lookup into executed outcome evidence and may only move the executor up (ENGINE-LAWS H4); this is the documented exception to the L0 review rule. The receipt records `source: shape-default` with the evidence ref. Missing or corrupt file = empty map plus a NOT PROVEN line, never a crash.

Before R1-19 merges, rerun B9 on the losing shape with the seeded file present to confirm Sonnet reaches parity there; if Sonnet also loses, it ships as `prior-default` in router-shape-defaults.json, plus a FAILURE-CLASSES row; it is not a release blocker for other shapes. Time and cost misses on a shape are recorded and routed the same way. FireLater#17 is binding: it must pass on whatever executor its shape resolves to.
