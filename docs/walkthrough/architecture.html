Loki Mode at a glance

Hand it an issue or a task. Get back a pull request, tested, with a receipt that says exactly what was proven. Three ways to see how that works.

Describes Loki Mode 10.6.6 (npm latest)

Everything you touch, in the order you touch it. Four steps: set up once, give it work, watch it go, and trust what comes back.

1
Set up once
  • npm i -g loki-modeBun comes bundled for your platform. No extra installs.
  • loki doctorChecks your setup and ends with one line: Ready, or the one thing to fix.
  • loki.yamlOptional. Models, repos, budgets, Slack, in one file. Works without it.
2
Give it work
  • loki owner/repo#123One GitHub issue to one pull request. GitLab and Jira issue links work too.
  • loki "fix the login redirect"A plain task, no issue needed.
  • loki backlog owner/repoAdd --all for a whole backlog: one isolated run per issue, in parallel, inside your budget.
3
Watch it go
  • loki dashboard startYour runs in the browser.
  • loki control serve PreviewThe new Control Plane: every run, live stage and history in one place. Set LOKI_CONTROL=1.
  • SlackA message when a PR opens, when a run needs your answer, and when it finishes.
4
Trust what comes back
  • A pull requestOnly the change the task needs. Unrelated edits are left out and listed.
  • loki verifyRe-checks the signed receipt. Anyone can check it offline with loki verify --pubkey.
  • loki-sealInside Claude Code, it stops your agent from saying done while tests are red or were weakened.

Every run ends with one clear answer

No hanging, no vague "done". One outcome, and an exit code your scripts can read.

VERIFIED

The checks ran and passed. The PR is ready to review.

ALREADY_SATISFIED

It is already done in your code. No pointless PR.

PARTIAL

Progress made, but something is not proven. It tells you what.

BLOCKED

It needs one answer from you, and asks one question.

FAILED

It could not do it, and says why. It never pretends.

What sits around the engine

Models and providers

  • Providers: Claude Code, Codex, Cline and Aider, chosen with --provider.
  • Model cascade: starts on a cheaper model and moves up only when a real test fails.
  • Your keys: runs on your machine. Only model calls leave it.

Proof and records

  • Event log: one events.jsonl per run under .loki/runs/, sealed with a signed final line.
  • Receipt: signed with a local Ed25519 key, created on first run. Edits show as TAMPERED.
  • Public key: loki keys export, so others can verify offline.

Seeing your runs

  • Dashboard: local web view of runs.
  • Control Plane Preview: a separate service (Bun, Hono, SQLite or Postgres). Runs ship their events to it, and the UI reads only real events.
  • Slack: webhook notifications.

Think of Loki Mode as a careful contractor for your code. You leave a work order. It does the job, has it inspected, and leaves you a signed note. You just say yes or no.

You leave a work order

"Add a search bar." It can be an issue on GitHub or one sentence.

For real: loki owner/repo#52

It looks around first

It reads your project. If the search bar is already there, it tells you, and stops. No wasted work.

For real: the ALREADY_SATISFIED outcome

It writes the checklist before working

Like an inspector writing the checklist before the builder starts, so the builder cannot bend the test to fit the work.

For real: the Wall stage

It does the job

An AI model you choose makes the change. It touches only what the job needs, not your other rooms.

For real: Claude, Codex, Cline or Aider

The inspection runs

Your project's real tests run. If something fails, it gets up to two tries to fix it. It never just says "trust me".

For real: Verify, then Fix

You get a signed note

A pull request to approve, plus a sealed receipt: what passed, what was not checked, what it cost, how long it took. Nobody can quietly change it later.

For real: the receipt and loki verify

Why people use it

Less babysitting

Give it a whole list of issues. It works through them and only comes back when it needs you.

No fake "done"

If tests were skipped, deleted or weakened, it does not call the work finished.

Your choice of AI

Use the model you already pay for. Runs on your own machine, free to use.
