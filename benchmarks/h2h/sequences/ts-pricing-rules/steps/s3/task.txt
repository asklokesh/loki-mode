Add a spend-threshold pricing rule and a rule registry that builds rules from text specs. First, following the same pattern as the existing rules in src/rules/ (bulkDiscountRule, percentOffRule, buyXGetYRule: a factory that validates its arguments and returns a PricingRule from src/rules/types.ts, used by priceCart in src/pricing.ts), create src/rules/threshold.ts exporting thresholdRule(minCents: number, offCents: number): PricingRule. The factory throws a RangeError unless minCents is a non-negative integer and offCents a positive integer. Unlike the other rules it looks at the running total: when runningCents >= minCents it returns { rule: "threshold:<minCents>", amountCents: -min(offCents, runningCents) }, and otherwise null (also null when that amount would be 0). Second, create src/rules/index.ts exporting class RuleError (an Error whose name is "RuleError"), ruleNames(): string[] returning ["bulk", "buy-x-get-y", "percent-off", "threshold"] (sorted), parseRule(spec: string): PricingRule and parseRules(specs: string[]): PricingRule[] (parseRule applied to each, in order). A spec is trimmed and split on ":" into a rule name and its arguments: "bulk:<minQty>:<centsOffPerUnit>" builds bulkDiscountRule, "percent-off:<category>:<percent>" builds percentOffRule, "buy-x-get-y:<sku>:<buy>:<free>" builds buyXGetYRule and "threshold:<minCents>:<offCents>" builds thresholdRule. Numeric arguments must be plain digit strings, and category and sku must be non-empty. A name that is not one of the four (including names like "toString") throws RuleError with the message unknown rule "coupon" (the name in double quotes); a known name with the wrong number of arguments, a non-digit or empty argument, or arguments the factory rejects with a RangeError throws RuleError with the message bad rule spec "<spec>" (the spec exactly as passed, in double quotes).
