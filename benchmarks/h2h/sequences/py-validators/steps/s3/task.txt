Add a postcode validator and a form-level validate_form to forms/validators.py, following the same pattern as the existing validators there (validate_required, validate_username, validate_email, validate_phone), which take the raw value and a field name, return the cleaned value and raise ValidationError(field, message) from forms/errors.py. First, validate_postcode(value, country, field="postcode"): apply validate_required with the same field first (blank raises "is required"); country is matched case-insensitively after stripping. For "US" the value must be exactly 5 digits or 5 digits, "-", 4 digits, and is returned unchanged. For "CA" it must be letter digit letter, an optional single space, digit letter digit, letters in either case, and is returned uppercased with exactly one space ("k1a0b1" returns "K1A 0B1"). An invalid value raises ValidationError(field, "must be a valid postcode"), and any other country raises ValidationError(field, "unsupported country FR") with the country code uppercased. Second, add a module-level dict VALIDATORS mapping exactly the names "required", "username", "email", "phone" and "postcode" to the five validator functions, and validate_form(data, schema) -> (cleaned, errors): schema maps each field name to a rule, which is a validator name, or "name:arg" to pass one extra argument before the field (so "postcode:CA" calls validate_postcode(value, "CA", field=<field>)); every other validator is called as validator(value, field=<field>). The value is data.get(field, ""), fields in data but not in schema are ignored, and every field in schema is validated. cleaned maps each field that passed to its cleaned value, errors maps each field that failed to the error's message only (like "is required"), and both dicts keep the schema's field order. A rule naming an unknown validator raises ValueError("unknown validator 'zipcode'") with the name quoted.
