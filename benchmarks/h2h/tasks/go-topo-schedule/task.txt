Add a build planner and a build simulator to the sched package, all in a new file sched/plan.go. Part 1, Plan. func Plan(tasks map[string][]string) ([][]string, error), where each key is a task and its value lists the tasks it depends on (duplicates in a list count once; a nil or empty list means no dependencies). On success it returns batches: batch 0 holds every task with no dependencies, and batch k holds every task not already placed whose dependencies are all in batches 0..k-1; each batch is sorted ascending. An empty or nil map returns an empty non-nil slice and a nil error. On any error Plan returns a nil slice. Errors are checked in this order. First, unknown dependencies: a dependency that is not itself a key of the map (even if it is listed as a dependency elsewhere) gives &UnknownDepError{Task, Dep} (exported struct type with string fields Task and Dep); if there are several, report the lexicographically smallest Task that has an unknown dependency and, for that task, its smallest unknown Dep. This check comes before cycle detection, so it wins even when the graph also has a cycle. Its Error() is exactly fmt.Sprintf("task %q depends on unknown task %q", Task, Dep). Second, cycles (a task depending on itself is a cycle): return &CycleError{Path} (exported struct type with field Path []string) whose Error() is "dependency cycle: " followed by the Path elements joined with " -> ", for example "dependency cycle: a -> b -> a". Path is canonical: let start be the lexicographically smallest task that lies on a cycle (a task that only depends on a cycle without being on one does not count). Path begins [start]. Then repeatedly, from the last task u on the path, choose the lexicographically smallest dependency v of u such that either v is start, or v is not already on the path and v can reach start by following dependencies without passing through any task already on the path (other than start itself). Append v; stop as soon as v is start. So a self-dependent task b gives [b b], and with p: [r, q], q: [s], s: [p], r: [p] the path is [p q s p], not the shorter [p r p]. Both error types are returned as pointers so callers can use errors.As. Part 2, Simulate. Add type Task struct { Deps []string; Duration int; Priority int } (Duration in minutes), type Slot struct { Start, End, Worker int }, type Schedule struct { Slots map[string]Slot; Makespan int; CriticalPath []string }, and func Simulate(tasks map[string]Task, workers int) (Schedule, error). It simulates a non-preemptive list scheduler on workers numbered 0..workers-1, starting at time 0. A task is ready once all its dependencies have finished. At each event time t (0, then every time some running task finishes), first process every task whose End is t: its worker becomes free and its dependents whose dependencies are now all finished become ready at t. Only after all completions at t, start tasks: while there is a free worker and a ready task, take the best ready task, ordered by higher Priority first, then longer Duration first, then name ascending, and give it to the lowest-numbered free worker (not the one that has been idle longest), with Start = t and End = t + Duration. Then move to the next earliest End among running tasks. Slots has one entry per task. Makespan is the largest End (0 when there are no tasks). CriticalPath is a dependency chain, listed in execution order (dependencies first): let weight(x) = x.Duration + the largest weight among x's dependencies (0 if none). Pick the end task among the tasks whose End equals Makespan, choosing the largest weight, ties broken by smallest name. Then repeatedly step to the dependency of the current task with the largest weight, ties broken by smallest name, until a task with no dependencies; reverse that list. With no tasks, Simulate returns non-nil empty Slots, Makespan 0 and a non-nil empty CriticalPath. Errors, checked in this order, return a zero Schedule: workers < 1 returns the exported sentinel ErrNoWorkers (checked with errors.Is); then any task with Duration <= 0 returns &InvalidDurationError{Task} (exported struct type with string field Task, reporting the smallest such task name) whose Error() is exactly fmt.Sprintf("task %q has a non-positive duration", Task); then the same *UnknownDepError and *CycleError that Plan would return for the dependency graph built from each task's Deps, with exactly the same selection rules. Part 3, scale. Both functions must be fast enough for large build graphs: Plan and Simulate (with 8 workers) must each return within 2 seconds for 200000 tasks with up to 5 dependencies each, including graphs with dependency chains 100000 tasks deep. Cycle reporting must meet the same 2 second limit for both functions, for example on a 200000-task graph whose only cycle is a ring of 100000 tasks (plus acyclic tasks the ring depends on and a long chain of tasks hanging off the ring), and on a graph with 50000 separate 2-task cycles plus a 100000-task chain leading into them. Task names are arbitrary strings, so alphabetical order has nothing to do with dependency order.
