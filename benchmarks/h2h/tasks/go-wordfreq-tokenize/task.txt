The word counts from wordfreq.TopN(text string, n int) []WordCount are wrong. "Don't" and "don't" are counted as two different words, "end." and "end" are counted separately, when two words have the same count they come back in a random order that changes from run to run, and TopN with a negative n panics. Please fix it (Tokenize is in wordfreq/tokenize.go, TopN in wordfreq/count.go). The rules I want: Tokenize(text string) []string returns the words in the order they appear, lowercased with strings.ToLower so it is unicode aware ("ÉCOLE" becomes "école"). A word is a maximal run of unicode letters, unicode digits and ASCII apostrophes ('); everything else, including hyphens, periods, quotes and all other punctuation, separates words, so "well-known" is two words. Apostrophes inside a word are kept ("don't", "rock'n'roll"), but leading and trailing apostrophes are removed from each run ("'tis" becomes "tis", "dogs'" becomes "dogs"), and a run that is empty after that is dropped. Text with no words gives an empty slice. TopN counts those words and returns them sorted by count descending, with ties broken by the word in ascending order (plain Go string comparison), so the result is always deterministic. If n is larger than the number of distinct words, return all of them; if n <= 0 or the text has no words, return an empty non-nil slice.
