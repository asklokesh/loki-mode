The one-line report from statkit::summary (src/report.rs) prints wrong numbers. summary(&[1.0, 2.0, 3.0, 4.0]) gives "n=4 mean=2.50 p50=2.00 p90=3.00" but it should be "n=4 mean=2.50 p50=2.50 p90=3.70"; shuffling the same values changes p50 and p90; summary(&[]) prints "n=0 mean=NaN p50=0.00 p90=0.00" instead of just "n=0"; and a NaN anywhere in the input turns the mean into NaN. The report itself just formats what the functions in src/stats.rs return, so please fix the statistics there (keep every signature: count(&[f64]) -> usize, mean(&[f64]) -> Option<f64>, median(&[f64]) -> Option<f64>, percentile(&[f64], p: f64) -> Option<f64>). Expected behaviour: NaN values in the input are ignored by all four functions, so count returns the number of non-NaN values and the others work only on those; mean, median and percentile return None when there are no non-NaN values; percentile returns None when p is NaN or outside [0, 100]; percentile must not depend on input order (sort a copy ascending, the input slice must not be changed) and uses linear interpolation between closest ranks: with the n sorted values x[0..n], rank = p / 100 * (n - 1), lo = floor(rank), hi = ceil(rank), result = x[lo] + (x[hi] - x[lo]) * (rank - lo), so the 0th percentile is the minimum and the 100th the maximum; median is percentile(values, 50.0). The report format stays "n=<count> mean=<m> p50=<p50> p90=<p90>" with 2 decimals, and is just "n=<count>" when the statistics are undefined (for example "n=0" for empty or all-NaN input).
