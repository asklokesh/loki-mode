Refactor shapekit so the shape logic lives in one place instead of being duplicated across src/area.rs and src/perimeter.rs. Add a new public module src/shape.rs (declared as pub mod shape in lib.rs, with Shape and ShapeError also re-exported from the crate root) containing: pub enum Shape { Circle { r: f64 }, Rect { w: f64, h: f64 }, Triangle { a: f64, b: f64, c: f64 } } deriving Debug, Clone, Copy, PartialEq; pub enum ShapeError { UnknownKind(String), WrongParamCount { expected: usize, got: usize }, NegativeDimension, InvalidTriangle } deriving Debug, Clone, PartialEq, Eq, with a std::fmt::Display impl that produces exactly the messages the current functions return ("unknown shape kind: <kind>" with the kind exactly as the caller passed it, "expected <expected> params, got <got>", "dimensions must be non-negative", "sides do not form a triangle"); Shape::parse(kind: &str, params: &[f64]) -> Result<Shape, ShapeError>, which matches the kind ASCII case-insensitively ("circle" takes [r], "rect" or "rectangle" takes [w, h], "square" takes [side] and becomes Rect { w: side, h: side }, "triangle" takes [a, b, c]) and checks in this order: unknown kind, wrong parameter count, any negative parameter, then the triangle inequality; and area(&self) -> Result<f64, ShapeError> and perimeter(&self) -> Result<f64, ShapeError>, which also validate shapes built directly (any negative dimension gives NegativeDimension, checked before the triangle inequality, which gives InvalidTriangle) and then compute pi r^2 / 2 pi r, w h / 2 (w + h), and Heron's formula (clamped at 0 before the square root) / a + b + c. Keep the current quirks: zero dimensions are valid, and a triangle is invalid only when one side is strictly greater than the sum of the other two, so degenerate triangles like [1, 2, 3] are valid with area 0. Then make the existing free functions area::area(kind, params) and perimeter::perimeter(kind, params) (still re-exported from the crate root with the same signatures returning Result<f64, String>) thin wrappers over Shape::parse plus the matching method, converting errors with to_string(). Existing behaviour of area and perimeter must not change in any way, including every error message.
