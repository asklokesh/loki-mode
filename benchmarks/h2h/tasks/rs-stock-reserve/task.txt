Add stock reservations to the stockkit crate. First, in src/order.rs add Order::quantities_by_sku(&self) -> Vec<(String, u32)> that returns one entry per distinct SKU with the quantities of all its lines summed, sorted by SKU in ascending string order, leaving out SKUs whose total is 0. Then in src/stock.rs add a ReservationId type (pub struct ReservationId(pub u64), deriving Debug, Clone, Copy, PartialEq, Eq, Hash) and a ReserveError enum (deriving Debug, Clone, PartialEq, Eq) with exactly the variants UnknownSku(String), Insufficient { sku: String, requested: u32, available: u32 } and UnknownReservation, and re-export both from the crate root next to Inventory and Order. Add these Inventory methods: available(&self, sku: &str) -> u32 is on_hand minus the units held by active reservations (0 for an unknown SKU); reserve(&mut self, order: &Order) -> Result<ReservationId, ReserveError> uses order.quantities_by_sku() and is all-or-nothing: it checks the SKUs in that sorted order and fails on the first one that is either not known (never passed to add_stock), giving UnknownSku(sku), or whose summed quantity exceeds available(sku), giving Insufficient { sku, requested: the summed quantity, available: available(sku) }; on any error nothing is reserved. On success every SKU of the order is held and a ReservationId is returned that this inventory has never returned before. An order with no non-zero quantities succeeds with a fresh id that holds nothing. release(&mut self, id: ReservationId) -> Result<(), ReserveError> frees the held units (on_hand does not change), and commit(&mut self, id: ReservationId) -> Result<(), ReserveError> ships them: on_hand of each SKU drops by the held quantity and the hold ends, so available is the same before and after a commit. Both return Err(ReserveError::UnknownReservation) for an id that is not active (never issued, or already released or committed). Existing behaviour of add_stock, on_hand, knows and the Order methods must not change.
