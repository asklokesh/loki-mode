The Roman numeral parser in src/roman.rs (crate romankit) is broken and far too lenient. from_roman("IV") returns 6 and from_roman("XIX") returns 21 (numerals that end in a subtractive pair are misread), and it happily accepts junk like "IIII", "IC", "VX", "MMMM", "IIV", lowercase "xiv" and the empty string. to_roman also returns Ok("") for 0 and Ok("MMMM") for 4000. Please make both functions strict, keeping their signatures to_roman(n: u32) -> Result<String, RomanError> and from_roman(s: &str) -> Result<u32, RomanError> and the existing RomanError variants (Empty, InvalidChar(char), NonCanonical, OutOfRange). The valid range is 1..=3999: to_roman returns Err(RomanError::OutOfRange) for anything outside it and the canonical numeral otherwise (current output for valid numbers is correct). from_roman must accept exactly the canonical numerals, meaning from_roman(s) returns Ok(n) if and only if to_roman(n) returns exactly s, and it reports errors in this order: an empty string gives Err(RomanError::Empty); otherwise, if any character is not one of the uppercase letters I V X L C D M, it gives Err(RomanError::InvalidChar(c)) where c is the first such character in the string (so lowercase letters and spaces are invalid characters); otherwise any string that is not the canonical form of a number in 1..=3999 (for example "IIII", "IC", "VX", "MMMM", "IIV", "XM") gives Err(RomanError::NonCanonical). from_roman never returns OutOfRange.
