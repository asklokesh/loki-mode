Extend exprkit::eval(input: &str, vars: &HashMap<String, f64>) -> Result<f64, EvalError> in src/expr.rs, which today only handles integers joined by + and -, into a full arithmetic evaluator with functions and implicit multiplication. Keep the signature; EvalError must keep deriving Debug, Clone, PartialEq and have exactly these variants: Parse { pos: usize }, UnknownVar(String), UnknownFunc(String), Arity { name: String, expected: String, got: usize }, Domain(String), DivByZero. Tokens: a number is one or more ASCII digits optionally followed by a '.' and one or more digits (3, 007, 0.5, 10.25); a number cannot start with '.', and a '.' not followed by a digit is a parse error at the position of that '.' (so ".5" fails at pos 0 and "5." at pos 1). An identifier starts with a lowercase ASCII letter or '_' and continues with lowercase letters, digits or '_' (uppercase letters are never valid; "x3" is one identifier). ASCII whitespace (space, tab, newline, carriage return) may appear between any tokens and is ignored. Grammar, lowest to highest precedence: expr = term (('+' | '-') term)*; term = unary (('*' | '/' | '%') unary | power)*, where the bare power alternative is implicit multiplication and is taken only when the next token is an identifier or '('; unary = ('-' | '+') unary | power; power = primary ('^' unary)?; primary = number | call | identifier | '(' expr ')'; call = identifier '(' [expr (',' expr)*] ')', and an identifier followed (after optional whitespace) by '(' is always a call, never a variable times a parenthesis. So + - * / % and implicit multiplication are left associative at the same level, ^ is right associative and binds tighter than unary minus, and the exponent may carry its own sign: -2^2 = -4, (-2)^2 = 4, 2^-1 = 0.5, 2^3^2 = 512, --3 = 3, 2--2 = 4, 7 % 4 % 2 = 1. With implicit multiplication: 2x = 2*x, 2 x = 2*x, x y = x*y, 2(3+4) = 14, (1+2)(3+4) = 21, 2(3)(4) = 24, 3abs(-2) = 6, 2x^2 = 2*(x^2), -2x = (-2)*x, 2^3x = (2^3)*x, 6/2(1+2) = (6/2)*(1+2) = 9, and 2x(3) is 2 times a call of a function named x. A number never starts an implicit multiplication, so "2 3", "(2)3" and "x 2" are parse errors at the second number. The whole input must be consumed. Any syntax error gives Err(EvalError::Parse { pos }) where pos is the byte offset of the first non-whitespace character that cannot be accepted at that point (for example "2 3" fails at 2, "1 + 2)" at 5, "()" at 1, "X" at 0, "1,2" at 1, "min(1 2)" at 6, "min(,1)" at 4, "min(1,)" at 6), or input.len() if the input ends where more was required (so "" fails at 0, "   " at 3, "(1 + 2" at 6, "1 +" at 3, "max(1" at 5). An empty argument list like "min()" is syntactically valid. The whole input is parsed before anything is evaluated, so a parse error always wins over every other error. Evaluation computes the left operand of a binary operator before the right one and returns the first error it hits: an identifier missing from vars gives UnknownVar(name); / or % whose right operand equals 0.0 (including -0.0) gives DivByZero; % is Rust's f64 remainder (sign of the dividend, so -7 % 3 = -1 and 7.5 % 2 = 1.5) and ^ is f64::powf. The functions are min and max (one or more arguments, smallest or largest value), abs (exactly one argument) and sqrt (exactly one argument). Function names are separate from vars: calling any other name gives UnknownFunc(name) even if that name is a variable in vars. A call is evaluated in this order: first an unknown name gives UnknownFunc(name), then a wrong argument count gives Arity { name, expected, got } with expected "1" for abs and sqrt or "at least 1" for min and max and got the number of arguments (both checked before any argument is evaluated), then the arguments are evaluated left to right, and finally sqrt of a value below 0.0 gives Domain("sqrt"). eval must also scale to very deep and very long inputs, so it cannot recurse once per nesting level or operator: it must handle, without a stack overflow when called on a normal test thread (default 2 MB stack) and each within 2 seconds in a debug build (cargo test's default profile), inputs such as 100000 '(' then 1 then 100000 ')', 100000 nested abs( calls around -3, "max(1, " nested 100000 deep around 5, 100000 '-' signs before a number, a chain of 100000 "1^" before a final 1, a 200000-term sum "1+1+...+1", and "(1)" repeated 100000 times, with every rule above (values, error kinds and parse error positions) unchanged at any depth.
