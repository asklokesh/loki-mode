Add version range matching to semverlite in a new module semverlite/range.py with satisfies(version: str, rng: str) -> bool, max_satisfying(versions: list[str], rng: str) -> str | None, min_satisfying(versions: list[str], rng: str) -> str | None and intersects(r1: str, r2: str) -> bool, using the existing Version class in semverlite/version.py for parsing and ordering (semver 2.0 precedence, so 1.0.0-rc.2 < 1.0.0-rc.10 < 1.0.0). A range is one or more sets joined by "||" (OR: the version satisfies if any set matches); inside a set, comparators are separated by spaces and all must match (AND). A comparator is an optional operator (>, >=, <, <=, =) written directly before a version; no operator means =. Versions in a range may be partial or use x, X or * wildcards: "*", "x" and the empty string match every version; "1", "1.x" and "1.x.x" mean >=1.0.0 <2.0.0; "1.2" and "1.2.x" or "1.2.*" mean >=1.2.0 <1.3.0. With an operator, a partial version works like this: ">1" means >=2.0.0 and ">1.2" means >=1.3.0; ">=1" means >=1.0.0 and ">=1.2" means >=1.2.0; "<1" means <1.0.0 and "<1.2" means <1.2.0; "<=1" means <2.0.0 and "<=1.2" means <1.3.0. A hyphen range "A - B" (spaces around the hyphen, exactly one version on each side) is inclusive: >=A <=B, where a partial A is filled with zeros and a partial B means below the next version, so "1.2 - 2.3" is >=1.2.0 <2.4.0 and "1 - 2" is >=1.0.0 <3.0.0. Tilde: "~1.2.3" is >=1.2.3 <1.3.0, "~1.2" is >=1.2.0 <1.3.0, "~1" is >=1.0.0 <2.0.0, "~0.2.3" is >=0.2.3 <0.3.0. Caret allows changes that do not modify the left-most non-zero part: "^1.2.3" is >=1.2.3 <2.0.0, "^0.2.3" is >=0.2.3 <0.3.0, "^0.0.3" is >=0.0.3 <0.0.4, "^1.x" is >=1.0.0 <2.0.0, "^0.x" is >=0.0.0 <1.0.0, "^0.0" and "^0.0.x" are >=0.0.0 <0.1.0. A full version in a range may carry a prerelease tag (for example "^1.2.3-beta.2" is >=1.2.3-beta.2 <2.0.0 and "~1.2.3-beta.2" is >=1.2.3-beta.2 <1.3.0). Prerelease rule: a version that has a prerelease tag only satisfies a set if, besides passing every comparator of that set, at least one comparator in that same set has a version with a prerelease tag and the same major.minor.patch; so 1.2.3-alpha.7 satisfies ">1.2.3-alpha.3" but 3.4.5-alpha.9 does not, 2.0.0-rc.1 does not satisfy "<2.0.0", 1.0.0-beta does not satisfy "*", and in "1.2.3-alpha.1 || ^1.0.0" the version 1.5.0-alpha matches neither set. max_satisfying returns the highest satisfying version exactly as the string appeared in the list (the list can be in any order), or None if none satisfies; min_satisfying is the same but returns the lowest. intersects(r1, r2) is True if and only if at least one valid semver version (any version at all, not just the ones written in the ranges) satisfies both ranges under all the rules above, prerelease rule included, and it gives the same answer whichever order the ranges are passed in. For example ">=1.0.0 <1.0.0" intersects nothing, "<=1.0.0" and ">=1.0.0" intersect (at 1.0.0), ">1.0.0" and "<1.0.1" do not intersect (only prereleases of 1.0.1 lie between them and neither range has a prerelease comparator for 1.0.1), ">1.2.3-alpha.3" and "<1.2.3-alpha.4" do intersect (1.2.3-alpha.3.1 lies between and both ranges have a 1.2.3 prerelease comparator), ">=1.2.3-alpha.1 <1.2.3" and "<1.2.3" do not intersect, and with || on either side the ranges intersect if any set of one and any set of the other share a version. An invalid range (for example "abc", ">=1.2.a", "1.2.3.4", "=>1.0.0", or a hyphen with a missing side like "1.2.3 -") raises ValueError from every function, including max_satisfying and min_satisfying when the list is empty and intersects when either range is invalid, and an invalid version string passed to satisfies raises ValueError too. These functions run on large dependency graphs, so they must stay fast on large inputs (standard library only): calling max_satisfying and then min_satisfying on the same list of 200000 version strings with a range of 50 OR sets must take under 2 seconds for both calls together, and a single intersects call on two ranges of 300 OR sets each must take under 1 second, on an ordinary laptop.
